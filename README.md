# Android APK Builder Template

This repository is a ready-to-use Android project template. You can paste code generated by AI tools like Claude, Grok, ChatGPT, etc., into the appropriate files, push to GitHub, and automatically get a downloadable APK from GitHub Actions.

**It supports simple apps as well as complex games (2D and 3D).**

## How to Use

1. **Clone or edit files directly on GitHub** (or use Git locally).
2. **Paste your AI-generated code**:
   - Main logic / Activities / Game classes: `app/src/main/java/com/example/myapp/`
   - Layouts: `app/src/main/res/layout/`
   - Manifest: `app/src/main/AndroidManifest.xml`
   - Dependencies: update `app/build.gradle.kts` if needed
3. **Commit and push** to the `main` branch.
4. Go to the **Actions** tab → the latest **Build Android APK** workflow run.
5. Download the **app-debug-apk** artifact once the build succeeds.

## Building Complex Games & 3D Games

This template can handle any Android code, including games. For best results with complex or 3D games:

### Recommended Approaches

1. **LibGDX** (Best for AI-generated code + automatic APK)
   - Excellent for 2D and 3D games.
   - Pure Java/Kotlin + Gradle — works perfectly with this CI setup.
   - AI tools generate LibGDX code very well.
   - To switch to LibGDX: Replace the project structure with a LibGDX project (use [gdx-liftoff](https://github.com/libgdx/gdx-liftoff) to generate one) and keep the GitHub Actions workflow.

2. **OpenGL ES / Vulkan** (Native Android)
   - You can write game code using Android's built-in OpenGL ES for 3D.
   - Paste your Activity + Renderer code into the project.

3. **Godot Engine** or **Unity** (For full 3D engines)
   - Export your game project and place the files here, or set up a dedicated workflow.
   - Godot has good GitHub Actions support via Docker images.
   - Unity requires GameCI + license activation (more advanced).

### Tips for Games
- Add game assets (images, sounds, models) under `app/src/main/assets/` or `res/`.
- For physics, graphics libraries, etc., add the dependencies in `app/build.gradle.kts`.
- The debug APK works great for testing on devices.

## Changing the App Package Name

Update these places if you want a different package:
- `app/build.gradle.kts` → `namespace` and `applicationId`
- Package declaration in all `.kt` files
- Move the source folder accordingly

## Notes

- This builds a **debug APK** (unsigned, easy to install for testing).
- For signed release APKs, additional setup with keystore secrets is needed.
- Make sure any new dependencies you add are available on Maven Central or Google Maven.
- If the build fails, check the Actions logs for errors (common issues: missing imports, wrong package names, unsupported APIs).

Happy building games!
